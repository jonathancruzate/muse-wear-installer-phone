## What it is

The phone half of the Muse Wear Installer lane as its own app
(Jonathan's order, 2026-11-11: "Make this a separate phone apk"):

- **`CommandService`** — foreground service (specialUse; the
  dataSync time-budget lesson from Device Assistance v1.4.2),
  30 s poll of the Worker command channel as device
  **`wear-installer`** (wearbridge lane), one command per fetch,
  heartbeat `wearbridge:report` every ~5 min and after every
  command. Boot receiver restarts it when the lane switch is on.
- **`WorkerClient`** — adapted from Device Assistance's, device
  identity `wear-installer`; report carries the `wear_install`
  mirror object (the Worker sanitizes and stores it under
  `wearbridge:report`). Base + secret are configured on-device in
  `MainActivity`'s setup screen (DA's WorkerClient/Store pattern);
  the secret is never hardcoded and never logged.
- **`WearGate`** — the ShellAllowlist-equivalent: accepts ONLY
  `wear_install_face` {label, https-url, sha256}; the
  `checkWearInstall` validator ported rule-for-rule (https-only,
  host required, no userinfo/whitespace/quotes, label token
  charset, exact sha256 shape). Android-free for JVM testing.
- **`WearInstallRouter` / `WearStatusService` / `WearProtocol`** —
  ported from Device Assistance v1.13 (streaming-hash download,
  NodeClient pick, MessageClient offer, ChannelClient stream,
  300 s verdict latch, typed failures). `LoopbackAdb.Result` became
  a local `Result`; the wire protocol is byte-identical to the
  watch app's.

## Relationship to Device Assistance v1.13 / v1.14

DA v1.13.0 added the same verb inside the bridge; that build is
**withdrawn as the lane's owner** by this split (annotation added
to `muse-device-assistance/docs/v1.13-wear-install-2026-11-11.md`).
DA v1.14.0 (the `voice_bridge` build) was built on the v1.13 tree
and therefore still inherits the wear verb in its binary — noted
here and in the v1.13 record; DA code and the v1.14 line were not
modified by this task. Wear commands must be enqueued with
`--device wear-installer` so they land in the wearbridge lane,
never on phonebridge.
